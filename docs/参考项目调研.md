# 参考项目调研（微信消息分类 / 学习通抓取）

> 目的：我们的关键词分类一直不够准，找几个真实在用的开源项目对照做法。
> 调研时间：2026-10-31

## 1. SWSP-Git/messageAIHelper（★4，Kotlin/Android，GPL-3.0）

Android 通知监听 + AI 解析 + 静默写系统日历。

链接：https://github.com/SWSP-Git/messageAIHelper

关键做法：

| 做法 | 说明 | 我们能借鉴的点 |
|---|---|---|
| 通知监听（NotificationListenerService） | 不读微信数据库，直接监听系统通知 | 手机端可以自己收消息，不必依赖电脑 |
| 关键词过滤（每应用独立 AND/OR 规则） | 先粗筛，再送 AI，省 token | 我们把关键词当"预筛"，不做最终判定 |
| 10 秒防抖去重 | 重复通知不重复调用 AI | 我们按 msg_id 去重，可再加时间窗 |
| AI 输出结构化字段 | 是否日程 / 时间 / 关键信息 / 行动建议 / 重要性高·中·低 | 重要性分级比 7 分类更好用 |
| 重要性分级默认隐藏低 | 列表只显示中高 | 我们现在用 relevance≥45，可换成三档 |
| 静默写日历 + 备忘录归档 | 两类分开 | 我们的「任务 / 消息」也是这个思路 |
| 可选本地小模型（MNN + Qwen2.5-1.5B 4bit） | 离线不耗额度 | 以后可考虑，但手机性能有限 |

**结论**：它的分类不靠规则，靠 AI；规则只做过滤。这正是我们最该改的地方。

## 2. DanMo661/Xuexitong-mcp（学习通 MCP，三件套 xxt + MCP + 桌面助手）

链接：https://github.com/DanMo661/Xuexitong-mcp

公开了真实接口（我们缺的那部分）：

| 功能 | 接口 |
|---|---|
| 通知中心 | `POST https://notice.chaoxing.com/pc/notice/getNoticeList`（游标翻页用 `notices.lastGetId`） |
| 考试列表 | `GET https://mooc1-api.chaoxing.com/exam-ans/exam/test/examcode/examlist`（服务端渲染 `<tr class="dataTr">` 表格：编号/名称/时间/时长/考试状态/作答状态/分数/方式） |
| 课表 | `POST https://kb.chaoxing.com/pc/curriculum/getMyLessons` |
| 登录 | `POST https://passport2.chaoxing.com/fanyalogin`，uname/password 用 AES-128-CBC（key=iv=`u2oh6Vu^HWe4_AES`） |

它的产品设计也能参考：

- **新增内容分级**：标题含 作业/HW/实验/报告/考试 → 高优弹窗；老师通知 → 中优；课件更新 → 低优只进时间线
- **考试看板**：进行中 / 未考 / 已结束三态 + 分数
- **巡检**：默认 30 分钟一轮，只读查询，节流 0.8s

**结论**：考试接口已按这个实现（见 `server/adapters/chaoxing_exam.py`），实测拿到 5 条考试。

## 4. 我们当前的问题与改法

现状：纯关键词打分（`message_classify.py`），规则越加越多，但语义判断永远追不上口语。

参考项目的共同点：**AI 做判定，规则做预筛**。

建议改造（分三步，风险从低到高）：

### 第一步：AI 分类（保留规则兜底）

- 关键词先粗筛：命中任何规则词、或长度 > 15 的消息 → 进 AI 队列
- 批量调用（20 条/次），输出 JSON：
  ```json
  {"items":[{"id":1,"category":"homework","is_task":true,"importance":"high","reason":"..."}]}
  ```
- 结果写回 `category` / `importance` / `classify_src='ai'`；失败或超时回退规则结果
- 只对「分类未定性」的消息跑（`classify_src` 为空），避免重复花钱

### 第二步：用户纠正 → few-shot

- 消息详情里加「分类不对？」→ 选正确分类
- 纠正记录存 `classify_feedback` 表，作为 few-shot 例子注入 prompt
- 同一条消息不再被 AI 反复判错

### 第三步：重要性三档替代 relevance

- 高（要交/要报名/有截止）/ 中（通知、安排）/ 低（课件、闲聊）
- 列表默认只显示中高，和 messageAIHelper 一致
- 阈值判断从"分数 ≥45"变成"AI 给档位"，更直观

## 附：我们已落地的部分

- 收件箱 + 考试抓取（`chaoxing_notice.py` / `chaoxing_exam.py`）
- 去重：`notice:<idCode>` / `work:<workId>` / `exam:<hash>`
- 自己发的消息不入库
- 短闲聊兜底（覆盖 作业/竞赛/通知 三类误判）
